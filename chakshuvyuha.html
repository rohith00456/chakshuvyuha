Chakshu-Vyuha

A low-cost sensor network that watches the ground above underground coal mines, and speaks up before a slow shift becomes a real problem.

01 — The problem

Ground that moves without an announcement

Digging coal out from underground changes how stress moves through the rock above it. Given enough time, that stress can deform the surface — cracking roads, tilting buildings, straining rail lines and mine infrastructure long before anyone notices.

Ground surveys and satellite radar can measure this kind of deformation well, but neither is built to watch many points, continuously, on a shoestring budget. That's the gap this project sits in — not a replacement for those tools, but a cheap, dense layer of eyes watching in between.

The name

Chakshu-Vyuha

Chakshu means eye. Vyuha is a battle formation — layers of defenders watching every approach. The system borrows that idea: several small sensing "eyes" spread across a site, each one quietly watching its own patch of ground, all reporting back to one place.

02 — How it's built

Four layers, from the surface down to a screen

The system reads top to bottom like the ground itself — sensing sits at the surface, and by the time data reaches the dashboard, it's been refined the way raw ore is refined into something useful.

SENSING

Where the eyes sit

Distributed nodes installed across the monitoring site each read tilt, vibration, relative displacement, and crack continuity at their own location.

COMMUNICATION

Getting the word out

RA-02 LoRa radios carry each node's readings back to a central hub over the air, so nothing needs a buried cable run to reach it.

PROCESSING

Making sense of it

The hub streams incoming packets to a computer, where they're cleaned, filtered, baselined against normal behaviour, and checked for patterns that break the pattern.

APPLICATION

The seam of value

A dashboard turns all of that into node status, a risk level, and an alert a person can actually act on — the point where raw signal becomes a decision.

03 — Inside a node

What's actually in the box

Every sensor node is built from a handful of inexpensive, off-the-shelf parts — nothing exotic, which is the point.

CONTROLLER

ESP32

The brain of each node — reads every sensor and manages what gets sent over the radio.

TILT + VIBRATION

MPU6050

An accelerometer and gyroscope pair that tracks how much a node has tilted and how much it's shaking.

DISPLACEMENT

String & rotary encoder

A string runs to a rotary encoder, turning small mechanical movement into an electrical signal.

RADIO

RA-02 LoRa

Long-range, low-power communication between each node and the central hub, no cabling needed.

ENCLOSURE

Field housing

A section of PVC pipe keeps the electronics upright and shielded during outdoor trials.

04 — Getting data home

Node → hub → laptop

Each node reads its sensors, checks the data is valid, and sends it out over LoRa. A hub near the site receives every node's packets and forwards them over USB to a computer running the AI layer and dashboard.

05 — Reading the signal

Teaching the system what "normal" looks like

Every reading passes through the same pipeline before it means anything:

Raw data→ Cleaning→ Filtering→ Baseline→ Features→ Anomaly detection→ Risk score

The features that matter most are absolute tilt, the change in tilt over time, displacement and its rate, vibration magnitude and variation, and crack status. Because labelled subsidence data is hard to come by this early, the anomaly layer leans on an unsupervised method — Isolation Forest — rather than trying to train a direct predictor from day one.

Worth saying plainly: this is an anomaly detector, not a validated subsidence predictor. It flags readings that break from a site's own normal behaviour — proving it actually forecasts subsidence needs a lot more field data than one prototype can gather.

06 — Turning signal into a decision

Three states, one glance

Every node settles into one of three states, so a person scanning the dashboard doesn't have to interpret raw numbers.

Normal

Readings sit inside the range the node has already shown to be ordinary for its site.

Warning

A meaningful deviation from baseline — enough to watch closely, not yet enough to escalate.

HIGH RISK — needs a calibrated threshold before field use

High risk

Strong or multiple abnormal signs at once. Triggers an alert — but the threshold for this state still needs calibration against real field data before it's trusted for safety decisions.

08 — Test plan

Five stages of evaluation

1

Calibrate each sensor

Every sensor is tested and calibrated on its own before it goes anywhere near a full node.

2

Integrate the node

All sensors are wired into the ESP32 and evaluated together as one complete unit.

3

Test LoRa range

Communication is checked across different distances and deployment conditions.

4

Run controlled trials

Deliberate displacement and tilt changes are introduced to see whether the system actually catches them.

5

Establish baseline & test detection

Collected measurements define normal behaviour, then anomaly detection is evaluated against it.

09 — Being straight about it

Where this stands today

A prototype should be judged on what it hasn't solved yet as much as what it has.

01Displacement is measured relative to the node, not as absolute geodetic movement.
02Low-cost inertial sensors drift and pick up noise over time.
03Long-term outdoor use needs real environmental protection, not a pipe and a jar.
04LoRa performance depends heavily on terrain, obstacles, and antenna placement.
05The machine-learning layer is only as good as the data it eventually sees.
06Risk thresholds need domain expertise and calibration, not just code.
07Extensive field validation stands between this and any safety-critical use.
